Wichtigste Infos und Pfade für das Projekt:
- Um dieses Projekt zu verstehen, lese zuerst folgende Datei: docs/verification-methods.md
- Das Projekt verwendet uv als Python package manager, halte dich daran.

Der relevante Code befindet sich in den Foldern und Dateien:
- src/typstpresenter/convert
- src/typstpresenter/verify
- src/typstpresenter/__main__.py
Weiterhin wird für Tests die Datei verwendet: tests/test_verify.py
Der restliche Code ist von einem früheren Versuch und nicht so wichtig. Kann ignoriert werden.

Die Testdaten sind in dem Folder: tests/data
Insbesondere die Folder tests/data/IBN_presentations und tests/data/IBN_presentations2 enthalten viele PowerPoint-Präsentationen, anhand deren das Projekt getestet werden kann.



Die Konvertierung von pptx zu typst funktioniert schon recht gut, allerdings gibt es noch eine Reihe von Problemen.

Spezifische Probleme sind (gehe diese als nächstes an, sobald du die generelle Schleife verstanden hast):
1. Der generierte Code ist nicht wirklich für Menschen editierbar.
- Benutze statt dem Still im aktuellen Code idiomatische Sprachelemente von Typst und keine absolute Positionierung soweit möglich.
- Zum Beispiel in tests/results_tmp/showcase/simple.typ: Slide 1 ist eigentlich recht einfach zu erzeugen, aber hat jetzt Anweisungen wie #place, #par, #text(size: 32pt) und einzelne Befehle für die einzelnen Bullet Points (zum letzten: stattdessen benutze die nativen Listen von Typst).
- Je einfacher der generierte Typst-Code, desto besser. Sollte die Platzierung von dem Original etwas abweichen, ist das kein Problem, solange es keine Überschneidungen der einzelnen Texte oder Bilder und Texte gibt und das Ganze vernünftig aussieht. Das heißt, Einfachheit von typst-Code damit für Menschen editierbar, und koherentes, fehlerfreies Layout ist jetzt wichtiger als Originaltreue. Eventuell musst du dafür neue Benchmarks und Tests erzeugen, um das schnell zu überprüfen, als Erweiterung der Verifikation Methode A und B.
- Mit diesem neuen Kriterium für Codeerzeugung kannst du von einfachen Beispielen zu immer komplizierteren gehen und Auto Research verwenden.

2. Der Code in dem Ordner src/typstpresenter/verify ist nicht besonders gut strukturiert, Gegebenenfalls auch der zugehörige Testcode. Teile den Code eventuell in Subpackages auf und restrukturiere auch den emitter.py um, sodass der Code besser wartbar ist und mehr den Prinzipien von Clean Code entspricht.
